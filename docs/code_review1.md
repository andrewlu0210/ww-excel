# Code Review 1

> 以下為原始審查紀錄；五項問題已於 v1.2.3 修正並加入回歸測試，詳見 [README](../README.md#v123-更新)。

變更仍存在欄寬匯出及條件格式顯示、往返儲存的問題。其中欄寬改變、自動橫條比例錯誤，以及橫條界限和隱藏數值設定遺失均已透過額外測試重現。

## 完整審查意見

### 1. [P2] 依輸出檔的一般樣式字型換算欄寬

位置：`internal/io/xlsxfile/write.go:468`

當原檔的一般樣式字型不同於儲存格預設字型，經 `.wwx` 重新開啟再匯出 XLSX 時，新檔的一般樣式會採用預設字型，但此處仍使用原檔的 ColumnDigitWidth。重新讀取後欄寬因此改變；以一般樣式 Arial 16 粗體、預設儲存格 Calibri 11 重現，308px 會變成 182px。應保留原本的一般樣式字型，或依實際輸出字型重新換算。

### 2. [P2] 區分資料橫條的自動界限與實際極值

位置：`internal/document/condfmt.go:246-249`

對全部為正數的資料，autoMin 應取 0，而不是資料最小值；全部為負數時 autoMax 也應取 0。目前將它們等同 min/max，會讓自動資料橫條的比例錯誤。例如資料為 10、20 時，10 的橫條應為一半，目前卻完全不顯示。請分別處理自動界限的零基準。

### 3. [P2] 同步寫入實心資料橫條的擴充界限

位置：`internal/io/xlsxfile/rules.go:195-200`

儲存具有固定上下限且啟用實心或邊框的資料橫條時，Excelize 會產生 x14 擴充，但其界限固定為 autoMin/autoMax，並未採用這裡的 MinValue/MaxValue。新的讀取流程又會以擴充規則覆蓋傳統規則，因此設定為 0～100 的實心橫條另存再開啟後就失去固定界限。需要同步修正輸出的 x14 門檻，不能只設定傳統規則的選項。

### 4. [P2] 合併擴充資料橫條時保留隱藏數值設定

位置：`internal/io/xlsxfile/conditionaldetails.go:161-162`

當傳統 dataBar 設有 showValue="0"，而對應的 x14 擴充未指定此屬性時，擴充物件的 HideValue 會是 false。整個替換 DataBar 會丟失傳統規則的隱藏數值設定，使原本只顯示橫條的儲存格重新顯示數字；實心且 HideValue=true 的橫條另存再讀即可重現。應逐項合併，保留未被擴充指定的設定。

### 5. [P2] 避免將未支援圖示集的儲存格顯示成空白

位置：`frontend/src/grid/renderer.ts:614`

匯入設定為只顯示圖示的 3Arrows、旗標或其他非交通燈圖示集時，drawConditionalIcon 會回傳 false，但此處仍依 hideValue 跳過數值，導致整個儲存格空白。這些規則現在都會被匯入，因此需要補上對應圖示，或對未支援的圖示提供數值退回顯示，避免資訊完全消失。
