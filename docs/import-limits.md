# 匯入資源限制與取消

WWX／XLSX（含 .xlsm）先檢查輸入，成功解析及公式計算後才替換文件。超限會顯示資源名稱與上限，原文件與其他視窗保留。開啟期間可按「取消」或 Esc；同一視窗開始另一個匯入時會取消舊工作，晚到的結果不能覆蓋新文件。

預設預算如下，MiB 為 1,048,576 bytes：

| 資源 | 上限 |
| --- | --- |
| 壓縮輸入 | 256 MiB |
| 解壓縮總資料 | 512 MiB |
| XLSX 單一 ZIP part | 128 MiB |
| ZIP part 數／名稱 | 10,000／1,024 bytes |
| JSON／XML 巢狀深度 | 128 |
| JSON 容器／XML element 記錄總數 | 4,000,000 |
| JSON／XML token 總數 | 64,000,000 |
| 一般 JSON 字串／單一 XML markup 或文字區段 | 512 KiB |
| JSON 非字串 scalar | 256 bytes |
| 工作表／實際儲存格 | 256／2,000,000 |
| XLSX 共用字串 | 2,000,000 |
| 樣式 | 65,536（XLSX 預檢計入所有 xf） |
| 儲存格文字 | 32,767 Unicode 字元 |
| 單一公式 | 64 KiB／4,096 tokens／128 層解析遞迴 |
| 模型中的儲存格與名稱公式總長度 | 32 MiB |
| 匯入公式計算 | 50,000,000 次受監測操作 |
| 公式中間陣列 | 1,000,000 元素，超限回傳 #VALUE! |
| 圖形 | 2,000 個；每個寬高 ≤8,192、面積 ≤8,000,000，合計 ≤32,000,000 邏輯像素 |
| 圖片資料／可辨識圖片像素 | 每張 64 MiB／每張與合計 64,000,000 像素 |
| 服務開檔期限 | 2 分鐘 |

各項限制會同時生效，因此未達其中一項上限也可能先碰到另一項。一般編輯使用同樣的公式解析與中間陣列限制；匯入專用的計算計數器只在開檔計算時啟用。XML 儲存格節點另有 65,536 字元預檢預算，包含公式、快取值與空白；最後模型文字仍限 32,767 字元。WWX 的 Data／XML／RawXML 等保存欄位使用獨立的 128 MiB JSON 編碼字串上限，圖片解碼後仍受 64 MiB 限制。

XLSX 不接受 DTD 等 XML directive（註解、CDATA、處理指令仍可使用）。XLSX 先複製成權限 0600 的暫存快照，直接計數 central directory 的實際記錄，再檢查所有 part 的實際解壓資料（含自訂 XML／圖形），後續解析使用同一份快照。WWX 在有界解壓與字串掃描後，先串流驗證 JSON 的結構和記錄數，再從暫存快照進行有界模型解碼。第二階段的 encoding/json 仍會配置文件緩衝區與模型，可能接近解壓總量，並非零拷貝讀取。暫存快照在成功、錯誤及取消時都移除；Excelize 自己使用的暫存檔仍由來源的 Close 清理。

取消採合作式檢查，涵蓋複製、解壓、JSON／XML 串流、模型轉換及公式計算。Excelize 等無 context 介面的第三方呼叫須等目前步驟返回，之後會丟棄結果並清理；2 分鐘是取消期限，並非可強制終止第三方函式的硬時限。本次針對 WWX／XLSX，CSV 未加入相同的串流預算。本機程序仍非隔離的工作程序，預算不是整個 App 的嚴格 RSS 上限，也不保證所有圖片解碼器或未知底層錯誤都可中斷。

驗證包含 8 MiB 單一儲存格的壓縮膨脹、大小／筆數／深度邊界、偽造 ZIP 記錄數、畸形 XML／JSON、gzip checksum、讀取中取消、平行公式計算取消、舊結果與視窗關閉競爭、暫存檔清理及原文件保護。原生取消流程用以下方式驗證（測試檔與報告只寫入暫存目錄）：

```sh
go run ./tools/bigfile -o /tmp/ww-import-qa/import-cancel.xlsx
WW_SELFTEST=1 WW_XLSX_FIXTURE=/tmp/ww-import-qa/import-cancel.xlsx \
  WW_BENCH_OUT=/tmp/ww-import-qa/cancel.md ./bin/ww-excel-display-fix
```

此安全檢查會增加開檔時間與短期記憶體配置，百萬格量測與範圍限制見 [perf.md](perf.md)。
